# Final export visibility

After export transaction COMMIT acknowledgement and the captured optional host authorizer's fresh final decision, `exportDocument` now starts a separate read-only, repeatable-read own-DB transaction. The selected document's current compartment visibility, exact document ref/content digest, editorial project, selected viewpoints and historical contributors must be accessible in this coherent snapshot before any new or cached response is returned. The final read COMMIT must itself acknowledge; unknown read outcome withholds content without undoing prior effects. No new schema, durable adapter or cross-engine database access is introduced.

Old immutable acknowledgements do not record credited collaborator IDs/project editions. Checking only the current project credits could silently drop an original private contributor. The guard therefore requires visibility of ALL collaborator IDs from ALL retained revisions of the selected document's original editorial project. This deliberately conservative check applies even to new exports that no longer include an older contributor. No latest-only fallback, omission, truncation, identity matching by name or history rewriting is allowed. The entire check denies when project history exceeds 1024 revisions, 512KiB of encoded credit metadata, 1024 unique collaborators or 1024 selected viewpoints. The aggregate byte/revision budget is checked before loading credit arrays. Missing/malformed historical metadata denies whole.

Final denial happens after the original export may already be committed/stored. The export, object, audit, event, immutable idempotency acknowledgement and all source/document revisions remain retained. An explicit identical replay with adequate current visibility returns that original acknowledgement without another put/export effect. Original command fingerprints and API shape remain unchanged. No automatic retry/rebase, cleanup, deletion or orphan repair is introduced.

## Limits and remaining work

The snapshot is current as of its first read after the export COMMIT/host callback, not a continuous permission lock. Writers can change state after that snapshot starts or after the final check. Original-human proofing/current roles/delegation, final SourceConsent/Knowledge/Factual permissions, approvals/withdrawals after their existing checks, complete recursive E09 source mapping and host lifecycle/PKI/TLS/driver/time-heap/browserAT acceptance remain separate. Existing pre-export checks remain unchanged; this guard does not establish whole-source rights, truth or distributed fencing. Returned copies are not revocable.

SQL and object storage are not a distributed transaction. Unknown object put or lost export COMMIT may leave retained uncertain state; this guard provides no stopped/no-output proof, rollback claim, retry authority or cleanup. Preserve uncertain objects and history for separately qualified reconciliation. A snapshot policy/context is not authentication.

Original six E09 units/dependencies, public15-engine/122-task four JSON files, schema, SDK pins/dependency versions and kit/contracts remain unchanged. All fixture data is fictional/private/country-neutral. No live input/provider use, sends, publication, payment, paid infrastructure or operational PAM is authorized.
